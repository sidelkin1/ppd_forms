Выгрузка проведенных ГДИС, ГТМ и соседних ГДИС для итогового заключения ИННЦ.

## Параметры для выгрузки
- **Отчет Сиам** -  файл с отчетом по ГДИС в формате Сиам;
- **Период ГТМ (мес)** – максимальная период проведения ГТМ до даты окончания ГДИС;
- **Период ГДИС (лет)** - максимальная период проведения ГДИС на соседних скважинах до даты окончания ГДИС;
- **Радиус** - максимальное расстояние до соседней скважины с ГДИС.

## Формат выходных файлов
В результате выгружается шаблон в формате Excel с информацией о прошлых ГДИС и ГТМ, а также замеры Рпл на соседних скважинах.

## Техническое описание

### Стратегия парсинга отчёта Сиам

Входной отчёт — файл интерпретации ГДИС в формате «Сиам», содержащий листы:

- **«Интерпретация»** — основная таблица с параметрами ГДИС в нормализованном виде. Релевантные данные располагаются в первых 4–5 столбцах (ключ, единица измерения, значение, источник и опциональный комментарий); остальные столбцы игнорируются. При наличии 5-го столбца он объединяется с 4-м для устойчивости к разным шаблонам отчётов.
- **«Титульный»** — содержит цель исследования. Применяется стратегия двух проходов: на первом проходе находится строка с заголовком «Цель» и фиксируется следующее непустое значение; на втором проходе ищется строка «Интерпретатор» — если она встречается, найденное ранее значение перезаписывается последним непустым перед ней. Это позволяет извлечь уточнённую цель вместо типовой, если интерпретатор добавил дополнительную формулировку.
- **«Доп.данные»** — содержит карту изобар. Извлекается самая верхняя по листу картинка (предполагается, что это карта изобар). При ошибке извлечения отчёт формируется без изображения.

Отчёт может поступать в старом формате `.xls`; в этом случае выполняется конвертация в `.xlsx`.

### Методика извлечения параметров ГДИС

Параметры извлекаются из таблицы «Интерпретация» путём сопоставления с регулярными выражениями (regex) по столбцу «ключ». Имена месторождения и скважины нормализуются через справочники замены, после чего пласты также проходят нормализацию. Дата окончания исследования разбирается с приоритетом формата `ДД.ММ.ГГГГ ЧЧ:ММ:СС` и откатом на автоопределение.

**Числовые параметры** — набор интерпретируемых показателей ГДИС, извлекаемых по устойчивым regex-шаблонам:

- **Проницаемость** (по жидкости, нефти или воде);
- **Скин-фактор** — в т.ч. в формулировках «полный», «совокупный»;
- **Пластовое давление на ВНК**;
- **Коэффициент продуктивности / приёмистости**;
- **Полудлина трещины** $X_f$.

Шаблоны учитывают вариативность написания (с/без дефиса, оценочные значения, формулировки «по КПД» / «оценочно»), что обеспечивает устойчивость к расхождениям в формулировках между интерпретаторами.

**Пластовые числовые параметры** — те же показатели, но привязанные к конкретному пласту (например, «Среднее пластовое давление на ВНК (Верейский)»). Шаблон формируется конкатенацией базового regex с экранированным именем пласта.

### Стратегия извлечения названий пластов

Названия пластов считываются из фиксированной строки таблицы «Интерпретация» и проходят двухэтапную нормализацию:

1. **Разбиение составных имён.** Строка может содержать как одиночные пласты (`«Верейский»`), так и перечисления (`«Верейский, Башкирский»`). Применяется словарь разбиения, восстанавливающий список канонических имён.
2. **Приведение к каноническому виду** — каждый элемент списка пропускается через справочник замены пластов.

Один загруженный отчёт Сиам может содержать несколько пластов — для каждого формируется отдельная запись результата.

### Стратегия сбора исторических данных

После парсинга отчёта запускается параллельный сбор исторических данных из локальной БД и OFM. При наличии нескольких пластов в отчёте все запросы выполняются с параметрами первой записи результата — это предполагает, что отчёт всегда относится к одной скважине и одному месторождению.

#### История ГДИС по скважине

Из локальной таблицы `WellTest` (аналитика для ГДИС) выбираются все записи для той же скважины и тех же пластов с датой окончания строго до даты исследуемого ГДИС. Записи упорядочиваются по пласту и дате.

Применяются следующие правила нормализации:

- **Скин-фактор** для видов исследований «КВУ», «КПД», «КВД», «КСД» по умолчанию принимается равным 0 при отсутствии значения — эти виды ГДИС всегда дают оценку скина.
- **Метка достоверности** «НЕИЗВЕСТНО» заменяется на «-» для замеров по миниГРП.
- **Проницаемость** выбирается первым непустым значением в порядке приоритета: по жидкости → по нефти → по воде.

#### История ГТМ по скважине

Из локальных таблиц `NewStrategyOil` (НС для нефтяных скважин) и `NewStrategyInj` (НС для нагнетательных) собираются ГТМ за период:

$$
T \in [\text{end\_date} - \text{gtm\_period}, \text{end\_date}]
$$

Для нефтяных скважин целевым пластом ГТМ считается `reservoir_after` (объект после ГТМ); для нагнетательных — `reservoir` напрямую. Тип скважины проставляется жёстко: «НЕФ» для нефтяных, «НАГ» для нагнетательных. Объединение записей — через `UNION`; сортировка по дате ГТМ.

#### Поиск соседних скважин (OFM)

Стратегия двухшаговая:

1. **Определение опорных координат целевой скважины.** По координатам интервалов заканчивания (`HeaderId.xcoord`, `HeaderId.ycoord`) для каждого пласта вычисляются средние координаты. При наличии нескольких интервалов заканчивания берётся геометрический центр.
2. **Поиск соседей.** Для всех остальных скважин того же месторождения и тех же пластов вычисляется евклидово расстояние:

$$
d = \sqrt{(x - x_0)^2 + (y - y_0)^2}
$$

где $(x_0, y_0)$ — опорные координаты целевой скважины в данном пласте. Скважины с $d \leq R$ (параметр **Радиус**) включаются в выборку. Имена скважин OFM приводятся к виду Сиам путём удаления суффиксов боковых стволов. Итоговые расстояния усредняются по паре (скважина, пласт).

#### Замеры Рпл на соседних скважинах (локальная БД)

Для каждого соседа (идентифицируемого композитным ключом `field + well + reservoir`) выбирается последний доступный замер ГДИС в интервале:

$$
T \in [\text{end\_date} - \text{gdis\_period}, \text{end\_date}]
$$

Отбирается запись с максимальной датой окончания; если в этот день зарегистрировано несколько видов ГДИС, берутся все. Такой подход даёт репрезентативную картину текущего пластового давления в окрестности исследуемой скважины без избыточной детализации истории.

#### PVT-свойства (OFM)

Из таблицы `ResPty` через цепочку связей `Reservoir2 → HeaderId → WellHdr → DictG` извлекаются начальное пластовое давление $P_{\text{нач}}$ (`initial_layer_pressure`) и давление насыщения $P_{\text{нас}}$ (`bubble_point_pressure`). Фильтр по `existence_type = 'ACTUAL'` гарантирует выбор актуальной записи свойств. Данные собираются для каждого пласта.

### Методика формирования итогового отчёта

#### Лист «Лист1» — служебные данные

Содержит три блока в фиксированных диапазонах:

1. **ГДИС по пластам** (столбцы A–L) — история ГДИС целевой скважины, сгруппированная по пластам.
2. **ГТМ** (столбцы N–T) — история ГТМ целевой скважины.
3. **Соседние ГДИС** (столбцы V–AC) — замеры Рпл на соседних скважинах. Номер скважины с пластом проставляется в формате `скважина (пласт)` для удобства идентификации пласта-источника замера.

#### Листы «отчет» — по одному на каждый пласт

Для каждого пласта создаётся отдельный лист путём копирования шаблона «отчет». При единственном пласте используется исходный лист без копирования. Листы озаглавливаются как «отчет (НазваниеПласта)».

**Заголовок** — формируется как «Результаты {вид исследования} {скважина} {месторождение}» с датой ГДИС.

**Таблица истории** объединяет ГДИС и ГТМ целевой скважины в хронологическом порядке. ГТМ, проведённые до даты первого ГДИС, исключаются. Фильтрация ГТМ по пласту использует подстроковый поиск — это позволяет привязать ГТМ к пласту даже при нестрогом совпадении имён (например, ГТМ на пласте «Вр,Бш» попадёт в отчёт по пласту «Бш»).

Строки ГТМ визуально отличаются: они заполнены серым фоном, неинформативные ячейки объединяются — отображаются только название ГТМ, дата и описание, а числовые параметры оставлены пустыми.

**График давления** — диаграмма, содержащая исторические замеры $P_{\text{пл}}$ и горизонтальные линии $P_{\text{нач}}$ и $P_{\text{нас}}$. Ось X масштабируется от первого числа месяца минимальной даты до первого числа месяца, следующего за максимальной датой:

$$
X_{\min} = \text{first\_day\_of\_month}(\min(T_{\text{end}})), \quad
X_{\max} = \text{first\_day\_of\_month}(\max(T_{\text{end}})) + 1\ \text{month}
$$

Ссылки на диапазоны данных в формулах серий перезаписываются с учётом нового имени листа — это необходимо для корректной работы формул при копировании листа на каждый пласт.

График и колонтитулы смещаются вниз на количество строк в таблице истории.

**Карта изобар** — извлечённое изображение масштабируется под фиксированный физический размер $91.0 \times 75.7\ \text{мм}$ с разрешением 96 DPI:

$$
\text{width} = \left\lfloor 91.0 \cdot \frac{96}{25.4} \right\rceil\ \text{px}, \quad
\text{height} = \left\lfloor 75.7 \cdot \frac{96}{25.4} \right\rceil\ \text{px}
$$

При масштабировании сохраняется соотношение сторон с обрезкой. Рядом с изобарами размещается изображение стрелки — указатель скважины. При отсутствии карты изобар в отчёте (или ошибке извлечения) отчёт формируется без неё.

Итоговый файл упаковывается в ZIP-архив.

### Ограничения подхода

- **Усреднение координат по интервалам заканчивания** для многозабойных скважин даёт координаты одного из стволов, а не фактической точки замера.
- **Сбор соседних ГДИС** ограничен одним последним замером на каждую пару (скважина, пласт) — динамика давления соседей не отслеживается.
- **Конвертация входного файла** в `.xlsx` при неподдерживаемом формате имеет ограничение по времени; при его превышении процесс может не завершиться.
