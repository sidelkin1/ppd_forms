Для некоторой группы отчетов требуется периодическое обновление данных в локальной БД.

## Обновление данных

Обновление данных осуществляется через вкладку **«Таблицы»** (рис. 2).

<figure markdown="span">
  ![Рис. 2. Активная вкладка «Таблицы»](/assets/images/fig_2.png)
  <figcaption>Рис. 2. Активная вкладка «Таблицы»</figcaption>
</figure>

Все таблицы локальной БД делятся на два типа по источнику данных:

| Тип | Источник | Способ обновления |
|---|---|---|
| **OFM (Oracle)** | Корпоративная база СМД | Автоматически по расписанию (cron) или вручную через API |
| **Excel** | Загруженный `.xlsx`-файл | Вручную: загрузка файла через API, затем обновление таблицы |

## Таблицы из OFM (СМД)

Данные загружаются из корпоративной базы СМД (Oracle/OFM). Обновление происходит автоматически **11-го числа каждого месяца в 00:00** (cron-задача в фоновом воркере) или вручную через эндпоинт `POST /api/database/{table}/{mode}` с указанием диапазона дат.

| Таблица | Содержимое | Режимы обновления |
|---|---|---|
| **МЭР** (`local_monthly_report`) | Месячные эксплуатационные рапорты: добыча нефти/жидкости, закачка воды по каждой скважине | `refresh` — добавить или заменить; `reload` — удалить и вставить |
| **ОПП** (`local_well_profile`) | Профили притока (ОПП): поинтервальное распределение притока/приемистости | `refresh` — добавить или заменить |

### МЭР (`MonthlyReport`)

| Поле | Тип | Описание |
|---|---|---|
| `field` | `str` | Месторождение |
| `well_name` | `str` | Номер скважины |
| `cid_all` | `str` | Список объектов разработки (через разделитель) |
| `cid` | `str` | Текущий объект разработки |
| `dat_rep` | `date` | Дата отчета |
| `oil` | `float` | Дебит нефти, т/сут |
| `oil_v` | `float` | Добыча нефти за месяц, т |
| `water_v` | `float` | Добыча жидкости за месяц, т |
| `water` | `float` | Закачка воды за месяц, м³ |
| `days` | `float` | Число дней работы |
| `oil_fvf` | `float?` | Объемный коэффициент нефти |

Вычисляемые поля:

- `liquid` — добыча жидкости (oil_v + water_v)
- `liquid_res` — добыча жидкости в пластовых условиях
- `watercut` — обводненность (water_v / liquid)
- `oil_rate`, `liq_rate`, `inj_rate` — суточные дебиты

### ОПП (`WellProfile`)

| Поле | Тип | Описание |
|---|---|---|
| `field` | `str` | Месторождение |
| `well_name` | `str` | Номер скважины |
| `cid_all` | `str` | Список объектов разработки |
| `layer` | `str?` | Индекс(ы) пласта |
| `rec_date` | `date` | Дата проведения исследования |
| `well_type` | `str?` | Характер работы скважины |
| `diff_absorp` | `float?` | Приток/приемистость из интервала, % |
| `tot_absorp` | `float?` | Суммарный приток/приемистость |
| `liq_rate` | `float?` | Дебит жидкости на дату ОПП |
| `remarks` | `str?` | Комментарии интерпретатора |

Данные загружаются из файлов `.xlsx`, предварительно загруженных через `POST /api/excel/`. После загрузки файла обновление запускается через `POST /api/excel/{table}/{mode}`.

## Служебные таблицы (мапперы)

Таблицы в схеме `utils` содержат правила замены наименований (маппинг) между различными источниками данных. Заполняются из CSV-файлов при инициализации (`poetry run task initialize`).

| Таблица | CSV-файл | Назначение |
|---|---|---|
| `utils.field_replace` | `data/field_replace.csv` | Замена названий месторождений |
| `utils.reservoir_replace` | `data/reservoir_replace.csv` | Замена названий объектов разработки |
| `utils.layer_replace` | `data/layer_replace.csv` | Замена индексов пластов |
| `utils.gtm_replace` | `data/gtm_replace.csv` | Замена названий ГТМ |

## Автоматическое обновление (cron)

Фоновый воркер (arq) выполняет обновление таблиц по расписанию:

| Задача | Расписание | Действие |
|---|---|---|
| `cron_refresh_mer` | 11-го числа каждого месяца, 00:00 | Загрузка МЭР из OFM за предыдущий месяц |
| `cron_refresh_opp` | 11-го числа каждого месяца, 00:00 | Загрузка ОПП из OFM за последние 2 месяца |
| `cron_clean_files` | 1-го числа марта, июня, сентября, декабря, 00:00 | Очистка каталога `files/` от результатов отчетов |

При ошибке каждая cron-задача выполняет до 3 повторных попыток с экспоненциальной задержкой.
