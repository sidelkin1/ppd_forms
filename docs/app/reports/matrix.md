## Параметры для выгрузки
- **Начальная дата** – начало периода расчета ГТМ ППД (формат `ДД.ММ.ГГГГ`);
- **Конечная дата** – конец периода расчета ГТМ ППД (формат `ДД.ММ.ГГГГ`);
- **На дату МЭР** (_необязательно_) – отчетный период формирования матрицы;
- **Базовый период** (_необязательно_, по умолчанию 1) – количество месяцев до даты ГТМ ППД (больше 0);
- **Прогнозный период** (_необязательно_) – количество месяцев после даты ГТМ ППД включительно (больше 0);
- **Исключаемые ГТМ НФ** – исключаемые мероприятия на НФ в прогнозном периоде для формирования базовой округи;
- **Список скважин** (_необязательно_) – файл с пользовательским списком скважин для расчета.

/// admonition | **Критично**
    type: danger
Хотя бы один из параметров **На дату МЭР** или **Прогнозный период** должен быть заполнен.
///

- **num_pred** - разница в месяцах даты **date_pred** относительно даты ГТМ ППД;

- **pred_watercut** - обводненность на дату **date_pred**;
- **pred_liquid_res** - добыча жидкости в пластовых условиях на дату **date_pred**;

- **neighbs_loss_liq** - окружение с соответствующим значением изменения дебита нефти из-за изменения дебита жидкости (суммарным по всем объектам);

## Техническое описание

### Источники данных

Расчёт опирается на три источника:

- **МЭР** (`monthly_report`) — помесячные показатели добычи и закачки: дебит нефти, жидкости, обводнённость, приёмистость, закачка, накопленные отборы/закачка в разрезе `(месторождение, скважина, объект, дата)`.
- **НС ППД** (`new_strategy_inj`) — перечень ГТМ на нагнетательном фонде: дата, описание, группа, проблемность, объект воздействия (`reservoir_neighbs`) и список соседних добывающих скважин (`neighbs`).
- **НС НФ** (`new_strategy_oil`) — перечень ГТМ на нефтяном фонде: дата начала ремонта (`start_date`), дата ВНР (`vnr_date`), наименование (`gtm_name`).

### Методика определения границ периода МЭР

Период выгрузки МЭР расширяется за пределы пользовательского интервала дат ГТМ, чтобы охватить базовый и прогнозный периоды для каждого мероприятия:

$$
H_{\text{мэр}}^{\text{от}} = H_{\text{гтм}}^{\text{от}} - k_{\text{баз}} \text{ мес.}
$$

$$
H_{\text{мэр}}^{\text{до}} = \min\big(H_{\text{мэр}}^{\text{отч}},\; H_{\text{гтм}}^{\text{до}} + k_{\text{прог}} - 1 \text{ мес.}\big)
$$

где $H_{\text{гтм}}^{\text{от}}$, $H_{\text{гтм}}^{\text{до}}$ — пользовательские границы периода ГТМ, $k_{\text{баз}}$ — базовый период, $k_{\text{прог}}$ — прогнозный период, $H_{\text{мэр}}^{\text{отч}}$ — дата МЭР из параметра **На дату МЭР**. Хотя бы один из параметров $k_{\text{прог}}$ или $H_{\text{мэр}}^{\text{отч}}$ должен быть задан — в противном случае правая граница не определена.

### Методика развёртки соседних скважин и объектов

Записи НС ППД хранят соседние скважины (`neighbs`) и объекты воздействия (`reservoir_neighbs`) в виде строк с разделителем. Для построения матрицы производится **развёртка (explode)** — каждая запись ГТМ порождает строки для каждой комбинации `(reservoir, neighbs)`, образуя декартово произведение «объект × соседняя скважина» в рамках одного ГТМ.

Если `reservoir_neighbs` не заполнено — в качестве объекта воздействия используется собственный объект нагнетательной скважины (`reservoir`).

### Методика определения границ эффекта ГТМ

Для каждого ГТМ на нагнетательной скважине определяются границы временного окна, в пределах которого оценивается эффект:

$$
H_{\text{баз}} = H_{\text{гтм}} - k_{\text{баз}} \text{ мес.}
$$

$$
H_{\text{кон}} = \min\big(H_{\text{мэр}}^{\text{отч}},\; H_{\text{гтм}}^{\text{след}},\; H_{\text{гтм}} + k_{\text{прог}} - 1 \text{ мес.}\big)
$$

где $H_{\text{гтм}}^{\text{след}}$ — дата следующего ГТМ ППД на той же скважине. Выбор минимума реализует стратегию **ограничения эффекта следующим ГТМ**: эффект мероприятия считается завершённым с началом следующего ГТМ на той же скважине, так как разделить вклады двух последовательных мероприятий в один период невозможно.

Временной интервал $[H_{\text{баз}}, H_{\text{кон}}]$ дискретизируется помесячно с шагом в один календарный месяц. Каждой дате $H_i$ в интервале присваивается номер месяца относительно даты ГТМ: $n_i = i - k_{\text{баз}}$, где $i = 0, 1, \dots$ — порядковый номер месяца от $H_{\text{баз}}$. Отрицательные значения $n_i$ соответствуют базовому периоду (до ГТМ), положительные — прогнозному (после ГТМ).

### Методика исключения ГТМ нефтяного фонда

Для корректной оценки влияния нагнетательного ГТМ необходимо исключить добывающие скважины, на которых в прогнозном периоде проводились собственные ГТМ, искажающие базовый уровень добычи. Стратегия:

1. Данные НС НФ разворачиваются помесячно в интервале $[H_{\text{нач}}, H_{\text{внр}}]$ — от даты начала ремонта до даты ВНР. ГТМ, попадающие в один месяц на одной скважине, конкатенируются через запятую.
2. Для каждого ГТМ ППД данные НС НФ присоединяются по совпадению `(месторождение, соседняя скважина, дата)`.
3. Если наименование ГТМ НФ (`gtm_name`) содержит хотя бы один из шаблонов, заданных пользователем в **Исключаемые ГТМ НФ**, — соседняя скважина помечается как исключаемая на весь срок действия данного ГТМ ППД.
4. Формируется столбец `neighbs_base` — соседние скважины за вычетом исключённых. Производственные показатели (дебит нефти, жидкости, обводнённость) присоединяются именно к `neighbs_base`, чтобы не зашумлять базовый уровень эффектом сторонних ГТМ.

### Методика распределения закачки

Показатели закачки из МЭР (приёмистость, месячная закачка, накопленная закачка) относятся к нагнетательной скважине в целом. Для расчёта влияния на конкретную соседнюю добывающую скважину применяется **равномерное распределение**:

$$
q_{\text{зак}, i} = \frac{q_{\text{зак}}}{N_{\text{сос}}}
$$

где $q_{\text{зак}}$ — исходный показатель закачки для нагнетательной скважины по данному объекту на дату, $N_{\text{сос}}$ — количество соседних добывающих скважин (`neighbs`) для данного ГТМ ППД (по тому же объекту и на ту же дату), $q_{\text{зак}, i}$ — доля закачки, приходящаяся на $i$-ю соседнюю скважину.

### Методика факторного анализа изменения дебита нефти

Расчеты проводятся согласно ЛНД ЗАО Компании П1-01.03 И-0033 [«Мониторинг и оперативный факторный анализ изменений дебитов добывающих скважин»](/assets/references/BP1-01-03_TTR-0033_IZM1.docx).

Изменение дебита нефти соседней добывающей скважины раскладывается на две составляющие интегральным методом — изменением дебита жидкости и изменением обводнённости. Интегральный метод обеспечивает аддитивность разложения.

**Нефтяная доля (oil cut):**

$$
f_{\text{н}}^{\text{баз}} = \frac{q_{\text{н}}^{\text{баз}}}{q_{\text{ж}}^{\text{баз}}}, \qquad
f_{\text{н}}^{\text{прог}} = \frac{q_{\text{н}}^{\text{прог}}}{q_{\text{ж}}^{\text{прог}}}
$$

При нулевом дебите жидкости нефтяная доля доопределяется значением из противоположного периода; если оба периода имеют нулевой дебит — принимается равной 0.

**Изменение дебита нефти:**

$$
\Delta q_{\text{н}} = q_{\text{н}}^{\text{прог}} - q_{\text{н}}^{\text{баз}}
$$

**Вклад изменения дебита жидкости:**

$$
\Delta q_{\text{н}}(\Delta q_{\text{ж}}) = \frac{f_{\text{н}}^{\text{баз}} + f_{\text{н}}^{\text{прог}}}{2} \cdot \big(q_{\text{ж}}^{\text{прог}} - q_{\text{ж}}^{\text{баз}}\big)
$$

**Вклад изменения обводнённости:**

$$
\Delta q_{\text{н}}(\Delta W) = \frac{q_{\text{ж}}^{\text{прог}} + q_{\text{ж}}^{\text{баз}}}{2} \cdot \big(f_{\text{н}}^{\text{прог}} - f_{\text{н}}^{\text{баз}}\big)
$$

**Проверка аддитивности:**

$$
\Delta q_{\text{н}} = \Delta q_{\text{н}}(\Delta q_{\text{ж}}) + \Delta q_{\text{н}}(\Delta W)
$$

### Методика агрегации потерь по окружению

Потери (изменение дебита нефти) агрегируются в два этапа для отображения в отчёте:

1. **Суммирование по объектам.** Для каждой комбинации `(нагнетательная скважина, ГТМ, соседняя скважина, месяц)` потери суммируются по всем объектам разработки — формируются три суммарные величины: $\sum \Delta q_{\text{н}}$, $\sum \Delta q_{\text{н}}(\Delta q_{\text{ж}})$, $\sum \Delta q_{\text{н}}(\Delta W)$.
2. **Конкатенация по окружению.** Для каждой комбинации `(нагнетательная скважина, ГТМ, месяц)` все соседние скважины с их потерями объединяются в строку вида `скв1 (знач1),скв2 (знач2),...`, формируя сводные столбцы `neighbs_loss_all`, `neighbs_loss_liq`, `neighbs_loss_wcut`. Строки, где `neighbs` пусто (нагнетательная скважина без соседей), в агрегации не участвуют.

### Ограничения подхода

- **Равномерное распределение закачки.** Закачка распределяется поровну между всеми соседними скважинами без учёта расстояний, проводимости пласта, схемы расстановки скважин или фактической гидродинамической связи. Это даёт оценку «сверху» для близкорасположенных скважин и «снизу» для удалённых.
- **Наложение эффектов последовательных ГТМ.** Стратегия ограничения эффекта следующим ГТМ корректна при условии, что мероприятия разделены во времени достаточно, чтобы эффект предыдущего завершился. При близких датах ГТМ разделение вкладов становится невозможным — эффект первого ГТМ может быть занижен.
- **Заполнение пропусков в накопленных показателях.** Отсутствующие значения `cum_water` и `cum_liquid_res` заполняются методом forward-fill с последующим backward-fill. На границах периода, где нет ни одного фактического значения, накопленный показатель принимается равным 0. Такой подход не учитывает накопление до начала расчётного периода и может занижать накопленные объёмы для скважин с большим сроком эксплуатации.
- **Независимость объектов разработки.** При развёртке `reservoir_neighbs` каждый объект рассматривается изолированно; межпластовые перетоки и взаимовлияние объектов через систему ППД не моделируются.
- **Приведение дат к началу месяца.** Все даты (`gtm_date`, `start_date`, `vnr_date`) округляются вниз до первого числа месяца. Для ГТМ, проведённого в конце месяца, смещение может достигать 30 дней, что вносит погрешность в привязку показателей МЭР к базовому и прогнозному периодам.
- **Неполнота данных НС НФ.** При отсутствии в СМД данных о ГТМ на нефтяном фонде механизм исключения не срабатывает — `neighbs_base` совпадает с `neighbs`, и эффект ГТМ НФ не вычитается из оценки влияния нагнетательного ГТМ.
